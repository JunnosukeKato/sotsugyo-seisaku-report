# 卒業制作報告書 作成ツール：引き継ぎ手順

このツールを担当する人が替わるときと、担当の人が年に何回か行う作業のための手順書です。
プログラムに詳しくない人でも、上から順に読めば分かるように書いています。

---

## 1. しくみ（全体の形）

| 部分 | 何をするか | 置き場所 |
|---|---|---|
| 学生用ツール | 学生が報告書を書き、PDF を書き出す | GitHub Pages（GitHub のリポジトリから自動で公開） |
| 管理ページ | 先生が年度の設定（題目・コース・指導教員・締切・ひな形・お知らせ・書き間違えやすい語）を編集・公開する | Google Apps Script「卒業制作報告書_管理」（管理用スプレッドシートに付属） |
| 管理用スプレッドシート | 年度の設定・変更履歴・管理者と先生の一覧 | Google ドライブ「卒業制作報告書_管理」 |
| 配信の窓口 | 学生用ツールに、公開中の年度の設定を渡す（誰でも読める） | Google Apps Script「卒業制作報告書_配信」 |
| ドライブ保存のログイン | 学生が大学のアカウントでログインし、自分の Google ドライブに原稿を保存する | Google Cloud のプロジェクト「sotsugyo-seisaku-report」（組織 bunka-wu.ac.jp、対象は「内部」） |

**学生の原稿と写真は、学生本人のブラウザと、学生本人の Google ドライブ（「卒業制作報告書」フォルダ）にだけ保存されます。**
学科のスプレッドシートやサーバーには集まりません。

## 3. 毎年の作業（管理ページ）

1. 管理ページを開き、「新年度を作成」で、前年度の設定をコピーして新年度を作る（「準備中」になり、学生には見えない）
2. 共通の題目・コース・指導教員・締切を直す。右の見本で表紙と抄録を確かめる
3. 必要なら、コースのカードで「下書きのひな形」と「このコースの学生へのお知らせ」を直す
4. 「この年度を学生に公開」を押す（前の年度は「終了」になる）
5. 学生用ツールの URL を学生に知らせる

- 原稿は、**書き始めた年度の設定で開きます**。新年度を公開しても、前年度の学生（留年など）の表紙は前年度のままです。新年度で書き直したい学生は、右の欄の「バックアップ」→「最初から作り直す」で新年度の原稿にできます（前の原稿は「自動の控え」に残ります）。
- 公開中の年度を保存すると、1分以内に学生のツールに反映されます。
- 変更履歴から、過去の内容に戻せます。
- ほかの人（先生など）が保存したあとに、古い画面のまま保存しようとすると、保存されずに知らせが出ます。ページを読み込み直してから、もう一度変更してください。

### 管理者と先生の登録

- 管理ページの「先生の登録」で登録します。メーリングリストの宛先をそのまま貼り付けて、まとめて登録できます（学生のアドレスと、大学のアドレスでないものは登録しません）。
- **管理者**：すべての設定の変更と公開、先生の登録ができる
- **先生**：どのコースの「下書きのひな形」「お知らせ」と、「書き間違えやすい語」を編集・保存できる
- 登録は、スプレッドシートの「管理者」シート（メールアドレス・メモ・役割）に入ります。役割は「管理者」か「先生」と書きます（空欄は管理者。それ以外の書き方の行は使えません）。

## 4. 担当が替わるときにすること

前の担当者と新しい担当者が一緒に行うと確実です。

1. **管理ページ**：新しい担当者を「管理者」として登録する
2. **管理用スプレッドシート**：新しい担当者に「編集者」で共有し、できれば学科の共有ドライブに移す（管理ページのプログラムはスプレッドシートに付属しているので、一緒に移ります）
3. **配信の窓口**（Apps Script「卒業制作報告書_配信」）：新しい担当者に共有する。持ち主が替わって公開し直すと URL が変わるので、そのときは `.env` の `VITE_CONFIG_API_URL` と `gas/deployments.json` を直して、学生用ツールを公開し直す（5 を参照）
4. **Google Cloud**：プロジェクト「sotsugyo-seisaku-report」の「IAM」で、新しい担当者を「オーナー」に加える。Google Cloud の画面に入るには、2段階認証の設定が必要
5. **GitHub**：リポジトリを新しい担当者（または学科の組織）に移す（Settings → Transfer）。移すと学生用ツールの URL が変わるので、学生への案内と、Google Cloud のクライアントの「承認済みの JavaScript 生成元」を新しい URL に合わせる
6. **反映の道具**：新しい担当者のパソコンに、5 の準備をする

## 5. プログラムを直して反映する

### 準備（はじめて1回）

1. Node.js（LTS 版）と Git を入れる
2. GitHub からリポジトリを取ってくる：`git clone https://github.com/JunnosukeKato/sotsugyo-seisaku-report.git`
3. フォルダの中で `npm install`
4. Apps Script に送るための道具にログインする：`npx clasp login`（大学のアカウントを選ぶ。https://script.google.com/home/usersettings で「Google Apps Script API」をオンにしておく）

### 直して確かめる

```
npm run dev       # 開発用のサーバー（http://localhost:5173）。?nodrive を付けるとログインなしで試せる（開発中だけ）
npm test          # 単体テスト
npm run e2e       # 画面の通しテスト（Edge を自動で操作。開発用のサーバーを動かしておく）
node scripts/e2e/admin.mjs   # 管理ページの通しテスト
```

### 反映する

- **学生用ツール**：`main` に送る（`git push`）と、GitHub Actions がテストして自動で公開する（数分）
- **管理ページと配信の窓口**：`npm test` が通ることを確かめてから `npm run deploy:gas`（URL は変わらない）

### 気をつけること

- 提出の締切の前（12月〜1月）は、組版の部品（`@vivliostyle/core`）を更新しない。ページの割り方が変わることがある
- このツールは AGPL-3.0 で公開している。直したら、GitHub にも必ず送る（動いているプログラムと公開しているソースコードを同じにする）
- 公開のリポジトリに、学生や教職員の個人のメールアドレス・個人のデータを入れない

## 6. 困ったとき

| こんなとき | すること |
|---|---|
| 学生がログインできない | ブラウザのポップアップを許可する。LINE や Classroom アプリの中で開いていたら、Safari や Chrome で開き直す。大学のアカウントを選んでいるか確かめる |
| 全員がログインできない（Google の障害・大学の設定変更） | 情報システムの担当に相談する。`drive-test.html` で、どの段階で止められているかが分かる |
| 管理ページの変更が学生に出ない | 公開中の年度を保存したか確かめる。反映まで1分かかる。学生はページを読み込み直す |
| 間違えて設定を変えた | 管理ページの「変更履歴」から、前の内容を読み込んで保存する |
| 学生が原稿をなくした | 右の欄の「バックアップ」→「自動の控え」、または学生の Google ドライブの「卒業制作報告書」フォルダの「原稿.json」（右クリック →「版を管理」で前の版）を確かめる |
| 共用のパソコンで書き終えた | 学生に、保存のようす（右の欄）→「この端末から原稿を消す」を押してもらう。Google からのログアウトも忘れずに |
